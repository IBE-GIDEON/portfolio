# Admin (no-database CMS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A password-protected `/admin` where Gideon edits all site content and uploads images; **Publish** commits everything to GitHub `main` in one commit and Vercel redeploys.

**Architecture:** Content moves from `site.ts` into `src/content/site.json`, validated by one zod schema shared by the site, the tests and the server. Admin API routes (Node runtime) check a signed session cookie, read the latest content from GitHub, process uploads with sharp (held client-side until Publish), and publish through the GitHub Git Data API. The public site stays fully static.

**Tech Stack:** Next.js 16.4 (App Router, Route Handlers, Cache Components), React 19.3, TypeScript, Tailwind v4, Motion, zod (new), sharp (moved to dependencies), Vitest, GitHub REST API via `fetch`.

**Spec:** `docs/superpowers/specs/2026-11-26-admin-cms-design.md`

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before using any Next.js API (`AGENTS.md`). Middleware is called Proxy in 16; this plan doesn't need it.
- Content file is **`src/content/site.json`** (next to `projectImages.json`; ruling vs the spec's `content/site.json`: same folder as the other generated content, no new top-level dir).
- Env vars: `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`, `GITHUB_TOKEN`; optional `GITHUB_REPO` (default `IBE-GIDEON/portfolio`), `GITHUB_BRANCH` (default `main`). Never logged, never sent to the browser, never committed.
- Cookie: name `gi_admin`, HttpOnly, Secure (except `NODE_ENV=development`), SameSite=Strict, Path `/`, Max-Age 7 days.
- Failed login responds after a 1000 ms delay.
- Upload limit 4 MB; accepted types `image/jpeg`, `image/png`, `image/webp`.
- Screenshot output 1200×750 WebP q72 + 24×15 WebP q45 blur (same as `scripts/optimize-project-images.mjs`); photo 512×512 WebP q80, `position: "attention"`.
- Admin-uploaded files are named `<id>.<hash6>.webp` under `public/projects/`, photo `public/me.<hash6>.webp`; hash = first 6 hex chars of sha256 of the WebP bytes.
- Admin look: black theme, System Settings layout, existing tokens (`bg-surface`, `text-muted`, `ring-white/[0.08]`) and `buttonStyles` from `src/ui/controls.tsx`.
- Work on branch `admin-cms` from `main`. Commit after each task locally. **Push / deploy only on Gideon's go-ahead**, and push `main` on its own (not together with another branch at the same commit).

## Review Focus

1. **Admin not set up yet** (env vars missing on Vercel) → `/admin` says "The admin isn't set up yet" instead of crashing; login returns 503. Pinned in Task 3.
2. **GitHub token wrong or expired** → Publish shows "GitHub rejected the access key. Check GITHUB_TOKEN in Vercel." and nothing is lost on screen. Pinned in Task 4 (client maps 401/403 to `AuthError`) and Task 5 (route maps it to 502 + message).
3. **Site changed since the admin loaded** (Gideon in two tabs, or a code push) → 409, edits kept, "Reload to get the latest". Pinned in Task 4/5.
4. **Project removed or screenshot replaced** → its old image file is deleted in the same commit and its manifest entry removed/updated; no orphan files, no stale cache. Pinned in Task 4 (`buildCommit`).
5. **Bad upload** (not an image, >4 MB, corrupt) → 415/413/422 with a clear message, nothing held. Pinned in Task 6.

**Files:**

**Interfaces:**
- Produces (`schema.ts`): `contentSchema` (zod), `type SiteContent = z.infer<typeof contentSchema>`, `type Project`, `type Service`, `type ExternalLink`, `type SectionId`, `type ProjectStatus`, `type ProjectGroupId`, and
  `validateContent(input: unknown): { ok: true; content: SiteContent } | { ok: false; errors: { path: string; message: string }[] }` (path like `projects.2.action.href`).
- Produces (`site.ts`): `export const site: SiteContent` (parsed from `site.json`; throws at import if invalid, so a bad file fails the build), plus `activeLinks`, and re-exports the types above. Existing imports of `@/content/site` keep working.

Rules the schema enforces: all strings trimmed non-empty except `photo` (`string | null`), `links[].href` (`""` or https URL) and `projects[].image` (optional, must start with `/`); hrefs `https://` only (WhatsApp `https://wa.me/…`); `projects[].id` unique and `^[a-z0-9-]+$`; `status ∈ {building, shipped}`; `group ∈ {products, client}`; `action` is `{label:"View", href:https}` or `{label:"Inquire", opens: SectionId}`; `links[].id` unique and one of the six; `email` valid; max lengths: names 80, short lines 160, paragraphs/descriptions 1200.

### Task 4: GitHub client and commit builder

**Files:**
- Create: `src/lib/admin/github.ts`, `src/lib/admin/github.test.ts`, `src/lib/admin/commit.ts`, `src/lib/admin/commit.test.ts`, `src/lib/admin/sections.ts`

**Interfaces:**
- `github.ts`: `class ConflictError`, `class GitHubAuthError`; `createRepoClient(cfg: { token; owner; repo; branch }, fetchImpl = fetch): RepoClient` where
  - `readFile(path: string): Promise<{ text: string; sha: string }>` (Contents API on `branch`)
  - `commit(input: { message: string; files: { path: string; content: string | Buffer }[]; deletes: string[]; expect?: { path: string; sha: string } }): Promise<{ commitSha: string; htmlUrl: string }>` — Git Data API: read `heads/<branch>` → if `expect` given and that path's current blob sha ≠ `expect.sha` throw `ConflictError` → create blobs (base64) → tree on head's tree with deletes as `sha: null` → commit with head as parent → `PATCH heads/<branch>` `force: false`; on 422 from the PATCH retry the whole sequence once, then `ConflictError`. 401/403 anywhere → `GitHubAuthError`.
- `sections.ts`: `type AdminSection = "profile" | "about" | "skills" | "projects" | "services" | "contact" | "socials"`; `changedSections(a: SiteContent, b: SiteContent, images?: HeldImage[]): AdminSection[]` (`profile` = any of name/alias/role/shortRole/pitch/location/timeZone/availability/stats/photo/seo; a held photo counts as `profile`, a held screenshot as `projects`). Used by both the commit message and the admin's Publish badge.
- `commit.ts`: `type HeldImage = { path: string; webpBase64: string; blur?: string; projectId?: string }`;
  `buildCommit(args: { current: { content: SiteContent; manifest: Record<string, { src: string; blur: string }> }; next: SiteContent; images: HeldImage[] }): { files: { path: string; content: string | Buffer }[]; deletes: string[]; message: string }`.

- [ ] **Step 1: Failing tests** (`commit.test.ts`): text-only change → files = only `src/content/site.json` (2-space JSON + trailing newline), message `Admin: update profile` (from `changedSections`); `changedSections(a, a) = []`, editing a service price → `["services"]`, a held screenshot → `["projects"]`; new screenshot for project `x` → files include `public/projects/x.abc123.webp` (decoded bytes) and `src/content/projectImages.json` with `x: { src: "/projects/x.abc123.webp", blur }`, and the old `public/projects/x.webp` in `deletes`; removed project → its image in `deletes` and its manifest key gone; an image still referenced by another project is never deleted; new photo → `public/me.<hash>.webp` written, old photo deleted.
